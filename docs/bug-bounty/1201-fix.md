# SRC-1201 fix and verification

Branch in both repositories: `fix-bounty-1201`.

- op-geth base: `7badaa8c0` (`develop`).
- opbnb base: `426567ebb` (`develop`).

## Implementation

op-geth now limits Optimism txpool-filled production to **7,388,608 canonical transaction bytes** (`8 MiB - 1,000,000`). The margin leaves room for block, batch RLP and signed SSZ encoding below the existing channel and gossip limits. The budget includes forced attributes and bundle transactions, follows environment copies used for MEV fallback, and is checked before executing each transaction. Only successfully appended transactions consume it; blob sidecars are excluded.

Oversized forced transaction prefixes fail synchronously in `buildPayload`, rather than leaving an asynchronous payload job that can never succeed. Existing sender-skipping and bundle-fallback behavior handles transactions that do not fit.

`NoTxPool=true` remains available for deterministic historical reconstruction. Non-Optimism production and block-import consensus rules retain their existing behavior. This change does not activate a hard fork or repair a previously canonicalized oversized block.

The runtime fix is in op-geth. The opbnb branch adds downstream compatibility tests, without changing gossip/channel limits or the published op-geth dependency. Deployment must upgrade the sequencer execution client to the fixed op-geth build.

## Reproduction and regression

On the unmodified `develop` implementation, the new miner regression produced 100 transactions with 130,000 zero calldata bytes each: approximately **13,010,700 transaction bytes**, while remaining within a 100M gas limit. Ordinary txpool, MEV fallback and direct bundle inclusion exceeded the budget; an oversized forced prefix was also accepted.

After the fix, the same txpool workload includes **56 transactions**, approximately **7,285,992 transaction bytes**, using **30,296,000 gas**. Both the ordinary path and MEV fallback preserve the forced prefix and remain below the byte budget. Forced-prefix and bundle regression tests pass. Separate tests verify boundary inclusion, rejection without state/gas changes, accounting after failed transactions, environment copying, historical reconstruction, and non-rollup compatibility.

Downstream tests exercise a near-budget block and the original oversized workload:

- Signed V3 gossip: the near-budget payload is accepted; the approximately 13 MB payload is rejected even though its compressed form is below the gossip limit.
- Singular and span batch channels: signed near-budget transactions with an L1-info deposit are accepted; the 100-transaction workload exceeds the channel RLP cap and is rejected.

## Commands

Run the miner suite in the op-geth checkout:

```sh
GOTOOLCHAIN=go1.25.12 GOSUMDB=sum.golang.org go test ./miner -count=1 -timeout=5m
go test -race ./miner -run '^TestPayloadSize' -count=1 -timeout=3m
```

Run downstream suites in the opbnb checkout:

```sh
GOTOOLCHAIN=go1.25.12 GOSUMDB=sum.golang.org go test ./op-node/p2p -count=1 -timeout=5m
go test ./op-batcher/batcher -count=1 -timeout=5m
go test ./op-node/p2p ./op-batcher/batcher -run 'Test.*PayloadSize' -count=1 -v -timeout=3m
```

The local default Go 1.27.3 triggers a QUIC/TLS session-ticket panic in the existing full P2P suite. Using the repository's configured Go 1.25.12 makes the full P2P suite pass. The targeted gossip and payload-size tests also pass on Go 1.27.3.
