- op-geth: based on `origin/develop`, `7badaa8c0`. This repository has no `develop-bug-bounty` branch.

## Change

Each list now records the complete reservation for each transaction: `tx.Cost()` plus the L1 estimate returned at insertion. Adding a transaction checks the L2 conversion, L1 conversion, combined transaction cost, and aggregate cost for uint256 overflow before changing any list state. A failed replacement preserves the original transaction, reservation, and thresholds.

All removal paths (`Forward`, `Filter`, `Cap`, `Remove`, `Ready`, and replacement) refund the saved reservation. Stateful replacement validation also refunds that same saved amount, rather than recalculating the old transaction's L1 fee using a newer estimator.

Reservations are insertion-time estimates. Head resets install the current estimator for new insertions; surviving transactions keep their saved reservations. A queue-to-pending move refunds the old queue reservation and creates a pending reservation using the current estimator. This makes additions, replacement checks, and removals consistent across L1 fee changes. It does not continuously reprice all pending transactions or change execution-layer fee charging.

The existing L2-only `costcap` and filtering behavior remain in place: `Filter` receives a balance reduced by `reduceBalanceByL1Cost`.

## Regression coverage

The new tests reproduce the original errors before the fix and cover:

- No L1 estimator, nil estimates, zero fees, and L1 fees above/below the L2 cost.
- Incorrect rejection of an affordable pair: total reservation 42,400 wei against a 50,000 wei balance.
- Incorrect acceptance of an unaffordable pair: total reservation 242,200 wei against a 200,000 wei balance.
- Underpriced replacement rejection and successful replacement, including L1 fee increases/decreases in real `validateTx` checks.
- Every removal method, strict invalidation, and clearing all reservations after a fee estimator result changes.
- Individual and aggregate uint256 overflow, rejection without mutation, and valid costs exactly equal to the uint256 maximum.
- Actual pool admission, head reset, nonce advancement, queue promotion, and final clearing using the real state-backed L1 estimator.

The original implementation failed these assertions, including the reset and L1-inclusive uint256-boundary cases verified through a temporary Go overlay. The fixed implementation passes the targeted regressions.
